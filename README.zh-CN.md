# Paper Workbench

[English](README.md) | **简体中文**

把读论文、问问题、记笔记放在同一个本地工作区里。

Paper Workbench 将连续滚动的 PDF 阅读器、AI 论文解读、可追溯来源的问答和个人文库结合起来。你可以接入自己的模型 API，也可以让已有的 Codex / Claude 会话生成内容，再保存到阅读器中。

项目的阅读体验受到 alphaXiv 启发，但属于独立实现，并非 alphaXiv 官方客户端。不需要 alphaXiv 账号，也不会发布公开评论。

## 能做什么

| 你想做的事 | 工作区提供的功能 |
| --- | --- |
| 整理阅读清单 | 导入网址或 PDF，用多级文件夹、标签、收藏和阅读状态整理文库。 |
| 理解论文 | 生成快速了解、深入研读或批判性阅读版本，指定关注点，保留多个版本和中英文翻译。 |
| 核对证据 | 从引用跳回 PDF，查看原始图表和页面截图。 |
| 追问细节 | 在侧栏流式问答，让助手查阅论文、通过视觉模型看图，并按需联网搜索。 |
| 留下阅读成果 | 高亮、划线、记笔记、回看翻译，导出笔记或带批注的 PDF。 |
| 使用自己的模型 | 保存多个 API 连接和模型列表，配置支持的思考等级，查看 API Token 用量。 |

**当前状态：**项目仍在持续开发，面向本地单人使用。部分浏览器回归测试尚待更新，见[发布前审查记录](docs/prepublication-review-2026-11-06.md)。目前还不是已经完成全部验证的公开发行版。

## 快速开始

需要安装 **Node.js 22.13 或更高版本**、npm 和 Git。

```sh
git clone https://github.com/SitaoXie/paper-workbench.git
cd paper-workbench
npm ci
npm run build
npm start
```

仓库保持私有期间，需要有访问权限的 GitHub 账号才能克隆。

打开 **[http://127.0.0.1:4318](http://127.0.0.1:4318)** 即可使用。导入论文、阅读 PDF 和记笔记不需要模型密钥；使用 AI 功能时，再选择下方的 API 或订阅代理方式。

### macOS 一键启动与重启

克隆项目后，双击 **启动文库.command** 启动文库；双击 **重启文库.command** 重新构建有变化的前端并重启。请先安装 Node.js。脚本会安装缺失的依赖、打开文库，关闭终端窗口后服务仍会继续运行。

也可以在终端操作：

```sh
npm run service:start
npm run service:status
npm run service:restart
npm run service:stop
```

重启会中断正在进行的模型请求，请等生成结束后再操作。日志和进程记录保存在 Git 忽略的 `.local-data/` 目录中。

## 从第一篇论文开始

1. **导入论文。**粘贴公开网页、arXiv/alphaXiv 链接、PDF 直链，或上传本地 PDF。
2. **选择解读风格。**想先掌握主旨，选“快速了解”；想看方法和证据，选“深入研读”；想检查假设与局限，选“批判性阅读”。也可以补充“重点解释消融实验，以及复现需要哪些条件”等要求。
3. **对照原文。**在摘要与 PDF 之间切换，点击来源引用、查看原图，核对模型的解读。
4. **追问和记录。**选中文字就地翻译、解释，单独发起问答，或添加笔记。
5. **整理文库。**把论文加入文件夹，设置标签和阅读状态。

如果 PDF 没有正确提取作者、机构或原始摘要，可以在文库使用“提取论文元信息”。选择模型后，先检查候选结果，再应用需要的字段。已有解读和笔记会保留，也支持撤销修改。

## 选择 AI 使用方式

| | 模型 API | Codex / Claude 会话 |
| --- | --- | --- |
| 如何配置 | 在“模型与 API”中保存接口地址、密钥和模型 ID。 | 在已经登录的代理中打开这个项目。 |
| 如何生成 | 本地服务器直接调用你配置的模型服务。 | 从网站复制任务，在代理会话中执行，再刷新网站查看结果。 |
| 如何统计 | 调用记录显示在“API 用量”中。 | 使用代理自身的订阅和额度，不计入本站 API 用量。 |
| 适合什么场景 | 在阅读器内直接提问、生成和翻译。 | 用已有代理订阅完成论文阅读和写作。 |

### 接入模型 API

打开“模型与 API”，新增连接，填写 Base URL、API Key 和模型 ID。同一个连接可以预填多个模型，也可以保存多个连接。生成解读前，先测试连接是否可用。

目前支持 **OpenAI 兼容的 Chat Completions** 和 **Anthropic Messages** 协议；其他服务需要提供其中一种兼容接口。助手的 agent 问答还要求模型支持原生工具调用。对于视觉模型，需要明确配置它支持图片输入，不能只凭模型名称判断。

支持思考控制的模型可以配置思考等级，或在已配置的不同思考版本之间切换。界面只展示已声明的控制项，不会让接口原本不支持的参数生效。回答风格包括均衡、简洁、详解和教学；内置提示词可查看但不可编辑，也可以添加自己的风格。

配置保存在本机服务端，重启后仍然有效。助手里的模型、风格、PDF 阅读方式和联网偏好也会持久化。移除连接或模型会将其停用，之后可以恢复。前端修改写入本地配置存储，**不会改写 `.env`**。

### 使用已有的 Codex / Claude 会话

项目自带一个[通用 skill](skills/paper-workbench/SKILL.md)，让代理读取已导入的论文，并将解读、翻译、图表和问答保存回本地网站。它不会读取你的订阅登录凭据，也不会把订阅转换成 API Key。

启动网站并导入论文后，通过“用 Codex / Claude”复制任务，粘贴到代理会话执行。也可以直接这样要求代理：

> 阅读 skills/paper-workbench/SKILL.md。使用当前会话，为论文 ID <paper-id> 生成一份中文深度解读。检查原文和相关图表，引用证据，将结果保存到 Paper Workbench。不要调用网站配置的模型 API。

将 `<paper-id>` 替换成网站或 CLI 返回的真实论文 ID。代理保存结果后，刷新阅读器即可查看。

可选的 Supervisor-Skills / ARS-Codex 下拉选项会把相应要求加入复制的代理任务。它**不影响直接 API 生成**，也不会安装这些 skill 或将它们打包进本仓库。需要在代理环境中另外准备，并遵守各自许可。详见[外部 skill 使用说明](skills/paper-workbench/references/external-skills.md)。

两条生成路径都使用项目的[阅读规范](skills/paper-workbench/references/reading-contract.md)。API 的深读和批判性阅读包含研究者、质疑者和编辑阶段；这些角色可能使用同一个模型，因此相互认同不等于独立验证。

## 阅读与笔记

### 解读版本与图表

同一篇论文可以保存多份解读，指定不同关注点，并切换中英文。首次翻译某个已保存版本可能调用模型，之后会复用该翻译，原版仍然保留。图文解读和交互导读都支持导出为独立 HTML。将已有解读转换成交互导读也会调用模型，执行前有确认步骤。

生成解读时，可以选择两种输入方式：

- **文字层 + 论文图表：**发送提取的文字和图片，并标注 PDF 页码及已保存的 Figure/Table 编号。没有裁剪区域的图表可能使用所在整页，并明确标注。
- **各页截图：**将页面截图交给支持视觉输入的模型。

默认一次发送全部图片。“每批图像数”设为 **0** 表示不分批；如果接口需要较小请求，可设置正数。纯文本写作模型可以配合单独配置的视觉理解模型；没有可用视觉模型时，回退为文字理解。保存的版本会记录实际使用的来源范围。

### PDF 与笔记本

PDF 支持连续滚动、文字搜索、目录导航，以及跳转来源后返回原阅读位置。页面会跟随明暗主题；检查图表配色时，可以切回原始颜色。

选中文字后可以高亮、划线、批注、翻译或解释。完成的 PDF 翻译和解释会留下可点击标记，并保存到笔记本；隐藏标记不会删除笔记。笔记支持标签、搜索、Markdown 预览、来源跳转、撤销，以及 Markdown/JSON 或带批注 PDF 导出。支持基础鼠标/手写笔绘制，但尚未实机验证压感和防误触。

### 研究助手

回答会在侧栏流式显示。模型接口返回的思考文本会在生成中展开，结束后自动折叠，也可以手动展开；不会尝试还原模型未返回或加密的内部推理。

助手可以读取完整的已提取页面，并在拿到工具结果后继续回答或调用工具。视觉模型还能请求整页 PDF、已保存的图表，或放大查看某个局部。论文问答中，15 页以内的 PDF 会按顺序提供可用文字；图片模式则提供页面截图。更长的论文先提供简要信息，再按需读页。工具轮数、传输大小和时间仍有边界，详见 [API 说明](docs/API.md#question-agent)。

使用引用回看证据。文字缺失、扫描页、匹配歧义或模型错误，都可能导致无法精确高亮段落。有些图表证据和整页总结适合使用页码引用，但仅有页码不代表某个具体段落已经核实。

“推荐问题”默认关闭，可在设置中启用并指定专用模型。开启后，打开论文助手可能自动生成推荐问题；点击问题只会填入输入框，不会直接发送。已有推荐会复用缓存，新生成的调用会计入 API 用量。

## 配置联网搜索

在助手中打开“联网”，允许外部搜索和网页读取。这个偏好会保存；新工作区默认关闭。

如果需要使用带密钥的搜索服务，在尚无 `.env` 时先从 `.env.example` 复制一份，然后填写：

```dotenv
TAVILY_API_KEY=your-search-key
PAPER_WORKBENCH_SEARCH_PROVIDER=tavily
```

修改 `.env` 后重启服务。未配置搜索密钥时，默认使用 DuckDuckGo HTML，但可能遇到验证或不可用的情况。搜索失败会明确显示，不会伪装成“没有结果”。

联网搜索会将搜索词发送到搜索服务，读取网页会访问外部网站。搜索服务额度与模型 Token 用量是分开计算的。

## 数据与隐私

这是一个**本地、单人使用的应用**，默认监听 `127.0.0.1`，不提供多用户身份认证。不要直接将服务暴露到公网。

| 数据 | 保存位置 |
| --- | --- |
| 论文、PDF、解读、笔记、会话 | 默认在 `.local-data/`，也可以通过 `DATA_DIR` 指定位置。 |
| 模型连接与 API Key | 本地配置存储；文件访问权限受限，但密钥**没有静态加密**。 |
| 服务端与搜索配置 | 可选的 `.env`，参考 [.env.example](.env.example)。 |
| API 用量 | 本地保存本站请求的统计；用量记录不包含提示词、回答、密钥或接口地址。 |

`.env` 和 `.local-data/` 已被 Git 忽略。如果使用自定义数据目录，请放在仓库之外，或自行加入忽略规则。源代码仓库与个人文库应分别备份。

“本地”指的是存储和应用服务。调用远程模型时，选中的文字、图片和问题仍会发送到你配置的模型服务；导入和搜索也会访问相应来源。运行本项目不需要学院账号或某台机器专用的接口。

“API 用量”页面展示输入/输出 Token、接口报告的缓存与思考用量、趋势和调用历史。未知用量不会当作 0，不完整统计会用 `≥` 标识。订阅代理导入和复用缓存翻译不会算作新的模型 API 调用。

## 配置与常见问题

| 需求或问题 | 处理方式 |
| --- | --- |
| 想换端口或数据目录 | 在 `.env` 或进程环境中设置 `PORT` / `DATA_DIR`。 |
| 模型响应较慢 | 调整连接的超时时间。流式生成按“多久没收到数据”计时，不按总生成时长硬切断；问答 agent 另有整体期限。 |
| 接口拒绝过大的输入 | 按服务要求调整上下文、图片分批或输出设置。字符预算和 Token 上限是不同单位。 |
| 模型似乎看不懂图 | 确认模型支持视觉并配置相应能力，或单独配置视觉理解模型。文字提取不等于读取了图片像素。 |
| 需要网络代理 | 按需设置 `HTTPS_PROXY`、`HTTP_PROXY`、`ALL_PROXY` 和 `NO_PROXY`。支持 HTTP(S) 代理地址，localhost 应放入 `NO_PROXY`。 |
| 需要自定义 DNS 解析 | 参考 [.env.example](.env.example) 的 `DNS_OVER_HTTPS_URL`；选择的解析服务会收到来源域名查询。 |

精确的参数、限制、持久化与错误行为见 [HTTP API 文档](docs/API.md)。代理导入格式和 CLI 示例见[导入指南](skills/paper-workbench/references/agent-import.md)。CLI 的 `publish` 命令只是保存到本地网站，并不是公开发布。

## 参与开发

```sh
npm run dev
```

打开终端打印的 Vite 地址，通常是 `http://127.0.0.1:5173`。开发服务器会把 API 请求转发到 4318 端口的后端。

```sh
npm test
npm run build
npx playwright install chromium
npm run test:e2e
```

浏览器测试使用独立服务和临时数据。**不要让测试连接你的个人文库。**测试隔离与贡献方式见 [CONTRIBUTING.md](CONTRIBUTING.md)，真实模型验证边界见[模型验证记录](docs/model-validation.md)，尚待完成的发布检查见[审查记录](docs/prepublication-review-2026-11-06.md)。
