# Reading-skill integration: independent review

Reviewed on 2026-10-25 against the working-tree implementation. This assessment covers integration behavior and evidence boundaries; it is not a release-wide visual approval or a certification of scientific correctness.

## Code and protocol assessment

No blocking defect was found in the reviewed shared-policy, subscription handoff, or standalone skill-bundle changes.

- The API reads a fixed, repository-owned reading contract. It does not discover personal skill directories, download upstream prompts, execute external hooks, or change providers. Overview, question, and translation instructions use separate scopes; translation does not receive the overview's review workflow.
- Both subscription reading entry points now use the same task builder. The main overview preserves explicit language, style, focus, presentation format, and optional companion selection. The generic bridge states its quick/article defaults. Explicit workspace binding is present on every supplied CLI command, and the import guidance distinguishes `summary.language` from top-level style/format/focus.
- Source review of the UI confirms that a prepared overview task is keyed to the paper, language, locale, style, format, focus, companion choice, and excerpt status. Changing those inputs hides the obsolete task instead of presenting it as the current configuration. This is source-level verification, not an exercised browser interaction.
- External companion guidance distinguishes separately available Supervisor-Skills and ARS-Codex from the application's own policy. It preserves upstream license boundaries, does not bundle upstream prompt text, and requires truthful disclosure when a selected companion is unavailable. The selected companion names are not substituted for the actual agent/model identity.
- Policy metadata records the application contract's identity and content hash. It is not a verification badge and does not claim that either upstream suite ran.

## Blinded provider-output assessment

The reviewer read only the labeled output packets and their embedded synthetic source, not the variant mapping or generation script. Each variant was a single stochastic sample from the same provider/model; this is a small diagnostic comparison, not an efficacy benchmark.

For the benchmark case, **A was preferred over B**, with reservations. Both retained the main counts, avoided ranking the systems from separate domain mixtures, and preserved the noncausal interpretation of context length. A cited the construction details and distinguished acknowledged limitations from a potential split concern. Its use of “leakage” to describe same-project questions is still too strong without a task/deployment definition: lack of demonstrated generalization to unseen projects would be more precise.

B introduced unsupported reasoning: it treated 100 versus 200 questions as a difference in sampling unit, though both units are questions, and referred to differences in evaluation budget despite the source stating a shared fixed retrieval budget. Sample size and resource budget are different quantities. Its description of a comparable framework also needed clearer separation from the unmatched X/Y results. These errors were retained in the review instead of treating a well-formatted overview as scientifically correct.

After that judgment was reported, the root disclosed that A used the candidate contract and B used the same provider with the new contract removed. This narrow preference does not establish general superiority. The candidate's own leakage wording remains a recorded weakness and motivated a general clarification separating shared-group splits, unseen-group generalization, and demonstrated contamination under the intended evaluation protocol.

Exactly one revised-candidate benchmark recheck was then reviewed with its identity known. It completed in roughly 42 seconds but **failed source fidelity**: it explicitly said sample, domain, and budget conditions all differed, although the source states a shared fixed retrieval budget. It also added an irrelevant finite-sampling maxim, used an awkward Chinese term for an uncertainty interval, and attached a source citation to an inferred lack of complete experimental detail. The leakage wording was less accusatory, but this did not make the overall reading acceptable. The original A was preferable in this one comparison. With stochastic, one-off outputs, this is not proof that the added sentence caused a regression; it is clear evidence that the updated prompt still does not reliably prevent unsupported statements.

The initial theory candidate request failed with status 502 after roughly 90 seconds. The elapsed time was consistent with the configured 90-second request limit, but the original harness did not retain an exact cause; a timeout is not proven. The baseline completed in roughly 84 seconds. At the first review checkpoint there was therefore no completed candidate for a fair pair. The baseline identity had already been disclosed before its content review, so that review was not blinded.

The theory baseline preserved the main conditional/asymptotic conclusion but failed source-faithfulness checks. It asserted that the paper did not discuss learning-rate selection based only on an excerpt that did not provide those details; assigned the fixed-rate negative result the same convexity/independence assumptions without source support; described the one-sentence fixture abstract as two sentences; and characterized proof rigor/alignment too confidently despite acknowledging that the full proof was unavailable. These are actual output failures, not evidence of defects in a real paper, since the source was synthetic.

One theory candidate retry used a 150-second timeout in copied evaluation settings, without changing production configuration, and completed in roughly 92 seconds. Its identity was known during review. It also **failed strict source fidelity**. The main theorem and its conditional/asymptotic limits were preserved, and it correctly distinguished unavailable proof text from proof absent in the paper. However, it later asserted that the paper did not position itself against prior convergence theorems or compare alternative frameworks, although the source only omitted that subject. It invented the absence of code/data/protocol from the fact that the paper was theoretical, and ranked independence as the most restrictive assumption without evidence. Repeated limitation and reproducibility sections also reduced readability. The partial successes do not outweigh these unsupported paper-level claims.

Those outputs were not regenerated to replace the failed records. A subsequent source review identified an implementation conflict worth correcting: the legacy critical-style instruction unconditionally requested baseline comparability and reproducibility gaps, while the new shared policy asked for a contribution-appropriate reading. The final code makes these checks conditional on relevance and supplied evidence, lets deep reading explain a method or argument, and makes the word limit a ceiling rather than a length target. This addresses an actual conflicting instruction instead of adding a fixture-specific list of banned conclusions.

The final wording passed another independent run of the same 33 focused tests. Its live theory recheck produced no content: the request returned 502 after 48 milliseconds, and one connection retry returned 502 after 24 milliseconds with the sanitized application message that it could not connect to the configured model API. These are recorded connection failures, distinct from the earlier roughly 90-second failure. No subsequent provider requests were used to obtain a passing answer. The final wording's effect on generated content remains unverified, and all earlier candidate failures remain part of this assessment.

The integration code and deterministic checks are acceptable within their reviewed scope, but the provider-generated reading-quality gate is **not passed**. Neither a broad quality improvement nor release/visual approval follows from this iteration. The failures should inform subsequent source-access and claim-review work rather than be hidden by additional prompt retries.

## Remaining verification boundaries

Browser access had previously been denied by the tool authority policy. This review did not attempt an alternate browser surface, direct debugging protocol, or browser-test workaround. Desktop/mobile rendering, click behavior, and visual layout therefore remain unverified for this iteration.

The code checks do not measure comprehension, source faithfulness on arbitrary papers, the efficacy of a separately installed upstream suite, or compatibility with a standalone Claude client. Any live model comparison must be reported separately with its actual source packet, observed failures, and sample limits.
