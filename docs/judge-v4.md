## Focused lessons from other readers

These are documentation-based comparisons, not claims of hands-on verification of those applications.

### Zotero: preserve source identity when a highlight becomes a note

[Zotero's official reader documentation](https://www.zotero.org/support/pdf_reader) describes annotation-to-note insertion with citations and a return-to-page action. It also offers a temporary selection mode and a locked highlighter mode for repeated marking. The most useful adaptation is a structured note that separates quotation, personal comment, and generated explanation while retaining the source anchor. A repeated-highlighting mode should be opt-in and visibly active, so ordinary selection for translation does not create unwanted marks.

The same documentation explains that Zotero stores reader annotations in its database; other PDF readers do not see them until an annotated PDF is exported. Our export UI should state whether a download is the untouched source, portable note data, or an actually annotated PDF. A Markdown note should retain a usable source link, and an export/import check should verify both the quote and its coordinates. This is a portability criterion, not a request to add every citation-manager feature.

### Sioyek: inspect evidence without replacing the reading task

[Sioyek's official usage guide](https://sioyek-documentation.readthedocs.io/en/latest/usage.html) documents in-place destination previews, searchable outlines, and a reading ruler. It can also guess a figure/equation destination when a PDF lacks a real link. The direct value is a small evidence peek before committing to a jump, matching the alphaXiv citation behavior inspected above. Guessed targets should be visibly distinguished from verified PDF destinations; a plausible but wrong figure is worse than a clear fallback. Its numerous native-app key bindings should not be copied wholesale into a browser, where common shortcuts already belong to tabs, history, and accessibility tools.

### Readest: make selection and page identity dependable

[Readest's official reading guide](https://www.readest.com/docs/reading) describes extending a text selection with the keyboard, selecting across PDF pages, joining visual line wraps when copying, and respecting printed PDF page labels. It also keeps a current-section row in the outline and can disable page thumbnails when they overwhelm a text-heavy document. These details suggest concrete future fixtures: a paragraph spanning two pages, a hyphenated visual wrap, and a PDF with roman-numeral front matter. Exported notes should distinguish printed labels from physical PDF indices. Keep a text outline as the default for papers; thumbnails should be optional. Its customizable selection toolbar is useful later, but a small stable default set should come before an additional configuration surface.

- After a subscription answer is loaded, the task panel still uses prepared/pending language such as “after the agent saves”; a completed-result message should make the observed state clear without deleting a newer draft.

This verdict does not claim that every model answer or visual analysis is scientifically correct. The lead reported the final browser regression run and focused fixture rechecks separately; this judge did not rerun or substitute those suites for actual UI exploration.

The checkpoint is suitable for continued development and user review within this scope. It is not an assertion of pixel-perfect equivalence, universal superiority to alphaXiv, absence of bugs, or readiness for unrestricted public deployment.
