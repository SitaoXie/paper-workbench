# 备份、迁移与升级

[English](UPGRADING.md) · [返回 README](../README.zh-CN.md)

论文数据和应用代码分开保存。更新 Git 不等于备份资料。升级前请等待导入与模型生成完成，并保留一份可恢复的备份。

## 可迁移的文库备份

在文库打开 **备份与恢复 → 下载备份**，将 `.paperwork` 文件保存在私密位置。导出与恢复都不会调用模型 API。

包含论文信息、文字层、原 PDF、各版阅读解读及译文、图表位置、互动导读、高亮、笔记、手写、段落翻译与解释、文件夹、收藏、阅读状态、聊天及图片附件。

**不包含**模型连接（含已停用的连接）、密钥、`.env`、API 用量、当前会话选择、推荐问题缓存或机器路径。元数据中含查询参数或凭据的网址也会移除。你写在笔记、聊天里的原文仍然保留，因此备份**不是匿名数据**，不能直接公开。论文图表可从备份中的 PDF 重新渲染；聊天上传的图片直接打包。

### 在另一套安装中恢复

1. 启动目标应用，可保留已有文库。
2. 打开 **备份与恢复 → 选择备份文件**。
3. 核对预览中的论文、PDF、解读、笔记、对话与文件夹数量。
4. 勾选确认后点击 **确认恢复**，等待完成再关闭页面。
5. 打开一篇导入的 PDF、一份解读和一条笔记检查。需要 AI 时，再单独配置目标机器的模型连接。

恢复采用**新增副本**，不覆盖已有论文或模型设置。论文、解读、笔记、对话 ID 和内部引用一起重映射；导入的顶层文件夹增加 `restored` 后缀。重复选择同一份备份并恢复，会产生重复论文。同一次确认请求在 15 分钟内重试不会重复导入。预览 15 分钟后失效，需要重新选择文件。

导入前会校验格式版本、记录关联、PDF/图片类型、体积以及 SHA-256 文件摘要。校验可发现损坏，不能证明文件来源；请使用可信备份。导出遇到缺失或无法读取的 PDF/附件会失败，不会悄悄遗漏。

### 体积限制与失败恢复

可迁移备份目前最多支持：压缩上传 **100 MiB**、解压后 JSON **200 MiB**、PDF/图片总量 **75 MiB**、单 PDF **25 MiB**、单聊天图片 **4 MiB**、论文 **10,000 篇**。这些是备份文件的安全限制，与模型的上下文或 token 配额无关。更大的文库，以及需要保留模型设置和 API 用量的完整迁移，请使用下面的停机备份。

导入失败时会保留原有记录。保存失败会移除本次新增记录，并尝试保存补偿状态，同时保留无关的并发修改。磁盘故障时请先恢复可写空间。若回滚也无法保存，应用会明确提示，并保留最后一次磁盘快照可能需要的 PDF；请重启检查文库后再决定是否重试，避免重复导入。失败后可能遗留不被引用的聊天图片文件，它们不会出现在文库里。确认恢复内容完整前，请保留原备份。

## 升级前的停机完整备份

完整备份包含密钥，适合做原样回滚。默认数据目录为 `.local-data/`；如配置了 `DATA_DIR`，请替换为实际目录。如果数据目录是符号链接，需要复制实际目录内容，而非只复制链接。

1. 等待当前请求结束。
2. 执行 `npm run service:stop`。如另开了 `npm start` / `npm run dev`，也要停止对应进程。用 `npm run service:status` 检查状态；其他实例仍在写入时不要复制。
3. 在项目目录执行，备份存放到**仓库之外**：

```sh
backup_dir="../paper-workbench-backup-$(date +%Y%m%d-%H%M%S)"
mkdir -m 700 "$backup_dir"
cp -a .local-data "$backup_dir/data"
if [ -f .env ]; then cp .env "$backup_dir/.env"; fi
git rev-parse HEAD > "$backup_dir/revision.txt"
```

这份备份含模型密钥、端点、PDF、附件和 `api-usage.jsonl`。不要提交 Git 或公开上传。反代服务等应用之外的配置需另外保留。

## 升级

先读目标版本说明，尤其是存储变更。项目仍在持续开发，旧版本不保证能读取新版本写过的数据库。

服务已停止且完整备份完成后：

```sh
git status --short
git fetch --tags
# 换成准备使用的版本标签；开发分支也可按自己的流程更新。
git switch --detach <release-tag>
npm ci
npm run build
npm run service:start
```

如 `git status` 显示自己的修改，请先保存，不要用 reset 覆盖。项目默认忽略 `.env` 和本地运行数据；自定义过 Git 配置时仍需检查。

启动后核对文库数量、文件夹、一篇 PDF、已有解读、笔记、对话及模型设置。新保存一条笔记，重启后应仍存在。开发版本还应运行 `npm test`、`npm run build`、`npm run test:e2e`；测试使用临时数据，不能替代实际资料核对。

## 回滚

再次停止服务。回滚需要恢复**匹配的代码与数据**；可迁移备份只是新增副本，不能代替回滚。

1. 将当前数据目录移到旁边保留，避免丢失升级后产生的新内容。
2. 将 `backup_dir/data` 复制回原数据目录；必要时私密恢复对应 `.env`。
3. 切换到 `revision.txt` 中的 Git 版本，执行 `npm ci`、`npm run build`，再启动服务。
4. 核对原论文与笔记后再考虑清理旧备份。

不要让两个应用进程同时写入同一数据目录。存储迁移可能在启动时发生，所以完整备份要在**第一次启动新版本之前**完成。
